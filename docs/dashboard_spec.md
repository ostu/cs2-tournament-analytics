# Спецификация будущего дашборда — CS2 Tournament Report (Audit v2)

Статус: **только спецификация**, без реализации интерфейса. Основана на `docs/source_audit.md`,
`docs/source_audit_v2.md`, `docs/metric_catalog.md`, `docs/powerbi_logic_audit.md`,
`docs/rating_semantics.md`, `docs/privacy_and_publication.md`. Везде, где метрика имеет статус
"формула отсутствует", это явно отмечено — на этапе реализации такие поля либо скрываются, либо
показываются с явной пометкой "требует подтверждения формулы". Обновления Audit v2 отмечены
**[v2]**.

---

## Общие принципы

- Целевая платформа — статический HTML (без backend, без React/Vue), встраиваемый в сайт.
  Все данные подготавливаются заранее в `mart_*`-таблицы и сериализуются в JSON/CSV, которые
  статическая страница читает и рисует на клиенте.
- **PII не выводится.** `fio`, `city`, `department`, `discord_name`, `faceit_name`,
  `faceit_link`, `steam_account`, `steam_name`, `id`, `player_id` из `players.xlsx` не попадают
  ни в один экран публичного дашборда.
- **[v2] Псевдонимизация игроков обязательна для публичной сборки.** Вместо `steam_name`/`id`
  используется `public_nickname`/`public_player_id` из `data/private/player_aliases.csv` (см.
  `docs/privacy_and_publication.md`). Названия команд — не PII, показываются как есть (после
  alias-нормализации написания). Перед публикацией — обязательный прогон
  `pipeline/check_publication_leaks.py` с кодом возврата `0`.
- **Команда — атрибут (игрок, турнир), не игрока в целом.** Любой экран, где отображается
  "команда игрока" без явного контекста турнира, должен либо использовать команду последнего
  турнира, либо требовать выбранный в фильтре турнир.
- **Alias-мэппинг команд обязателен до вывода данных.** Кандидаты — в
  `config/team_aliases_review.csv`; 4 группы требуют ручного подтверждения перед использованием
  (Brainrot/brainrot, RunChickenRun/RunChikenRun, Boys next door.../♂...♀, Мидоеды/мИдоеды).
- **[v2] `tournament_number` ≠ `rating_stage`.** Глобальный фильтр "турнир" должен фильтровать
  по `tournament_number` (1..7), а не по текстовому коду (`"1t"`, `"t1"`, `"1a"`) — иначе
  калибровка/нормализация/сам турнир будут либо теряться, либо задваиваться при агрегации
  (см. `docs/rating_semantics.md`, доказанный на `EloFinal` пример расхождения до 780 очков).
- **[v2] `result`/`PP` требуют предварительной очистки.** 79.9% строк `result` в
  `tournament_results.xlsx`, вероятно, испорчены Excel'ем (см. `docs/powerbi_logic_audit.md`,
  §3) — любой визуал, использующий счёт карты или `PP`, должен либо явно исключать
  невосстановленные строки, либо помечать их как "восстановлено эвристически" (см.
  `docs/unresolved_questions.md`, §2.2). Не показывать `PP`/счёт как надёжные данные без этого
  шага.

## Overview

**Назначение:** входная страница с общей картиной по всем турнирам.

- **Основные KPI** (карточки): количество турниров, количество игроков, количество команд,
  количество сыгранных карт, дата последнего обновления данных. Статус: подтверждена/частично
  подтверждена — можно показывать сразу.
- **Рейтинг команд** — топ-N команд. Формула "рейтинг команды" **всё ещё не найдена** ни в
  notebook, ни в `dax.txt` [v2: подтверждено отсутствие меры после разбора всех 17 мер]. Вместо
  рейтинга — показывать подтверждённое **место на турнире** (`tournament_score.place`) с явным
  выбором турнира в заголовке.
- **Рейтинг игроков** — топ-N по Elo. **[v2] `EloFinal` теперь подтверждён**
  (`elo_calib + Σelo_diff` по картам стадии `t` = `players.t{n}_elo`, точное совпадение на всех
  7 турнирах) — можно использовать как основание сортировки без оговорки "предварительно".
  Явного `RANKX`-измерения всё ещё нет — ранг вычисляется сортировкой на этапе построения витрины,
  не переносится DAX-мерой (её не существует).
- **Biggest gainers / losers** — топ игроков/команд по изменению Elo за последний
  турнир/период. Считается из `elo_changes` (подтверждено на уровне карты) — агрегация до "за
  турнир" должна суммировать **только карты стадии `t`** (см. общий принцип выше), не смешивать
  с калибровкой.
- **Общие фильтры (глобальные для всей страницы):** `tournament_number`, `team` (см. раздел
  "Глобальные фильтры" ниже).

### Общая страница игроков

- Рейтинг игроков — сортировка по `EloFinal` (теперь подтверждён, см. выше).
- **[v2]** Сравнение `elo_calib` и `EloFinal` по командам — формула `EloFinal` больше не
  блокер; блокер теперь только способ агрегации Elo по составу команды (сумма vs среднее — не
  подтверждено ни в notebook, ни в DAX).
- Количество сыгранных карт — подтверждено, прямой `COUNT`.
- Фильтры по `tournament_number`, `team`, `steam_name`(→публично `public_nickname`) —
  совпадают с глобальными + локальный поиск по игроку.
- Дата последнего обновления — из `date_max` в `tournament_results`.

### Страница отдельного игрока

- `elo_start`, `elo_calib` и итоговый Elo по турнирам — подтверждено.
- **[v2] Динамика Elo — теперь с полным рейтинговым циклом.** Последовательность строится по
  `rating_stage_order` (`Na=10 → Nc=20 → Nn=30 → Nt=40`, см. `docs/rating_semantics.md`), а не
  только по картам основного турнира — это ближе к тому, что реально показывает
  `player_elo_diff` в Power BI (объединяет карточные и стадийные изменения в одну
  последовательность). Waterfall/линия должны явно подписывать переходы между стадиями (вход →
  калибровка → блендинг [только для турниров, где стадия `n` зафиксирована — сейчас только
  турнир 7] → турнир), не просто "карта 1, карта 2, ...".
  - Линия с накопительной суммой — для обзора за несколько турниров (как в Audit v1).
  - Waterfall — для одного турнирного цикла (все стадии этого цикла), не для одной карты.
- Таблица `elo_diff` по картам — подтверждена.
- Места команды на турнирах — подтверждено, но только для команд, прошедших alias-нормализацию.

## Teams

- **[v2]** `EloFinal` на уровне команды больше не блокирован формулой (она подтверждена) —
  остаётся открытым только способ агрегации по составу (сумма/среднее). `elo_diff%` — формула
  подтверждена (база `elo_calib`), агрегация по составу — тот же открытый вопрос.
- **Профиль команды:** состав на каждый турнир, место на турнире (подтверждено), сыгранные
  карты и результат (`w/l`, подтверждено).
- **Waterfall изменения рейтинга по турнирам и картам:** та же рекомендация, что для игрока —
  один waterfall на турнирный цикл (все стадии), bar chart между циклами.
- **Результаты по турнирам:** таблица `tournament × place × w/l-сводка` — подтверждено.
- **[v2] Вклад карт:** ЕСТЬ подтверждённая денормализованная DAX-метрика для команды —
  `_TeamsPP` (раундовый дифференциал, `PP/5`), но НЕ для `elo_diff` (агрегация `elo_diff` до
  команды не реализована ни в одной мере). Рекомендация: реализовать team-map `elo_diff` как
  сумму по составу (аналогично `_TeamsPP`, но без хрупкого деления на константу 5 — считать
  напрямую на грейне tournament×mapId×team, см. `docs/powerbi_logic_audit.md` §4).

## Team × Map

- **Строки** — команды (после alias-нормализации).
- **Столбцы** — карты (`de_ancient`…`de_vertigo`, 8 подтверждённых значений).
- **Значения — переключатель метрики:**
  - Σ`elo_diff` команды на карте (см. Teams выше);
  - количество сыгранных карт (`COUNT`, подтверждено) — обязательный **sample size**, всегда
    рядом с значением;
  - **[v2]** раундовый дифференциал (`PP`/`_TeamsPP` из DAX, подтверждённая формула) — требует
    предварительной очистки `result` (79.9% строк потенциально испорчены, см. общие принципы) —
    **не включать в переключатель до решения по восстановлению `result`**, либо явно помечать
    ячейки, где значение основано на невосстановленных данных;
  - win rate на карте (`w/l`, подтверждено, не зависит от `result`-парсинга) — безопасный
    третий слой уже сейчас.
- **Условное форматирование:** heatmap + **minimum sample threshold** (< 3 карт — приглушать).
- **Итог по строкам и столбцам:** сохранить.
- **Сортировка:** по итоговому столбцу по умолчанию.

## Что стоит заменить

- Waterfall на всю историю игрока/команды → линия с накопительной суммой; waterfall — на один
  турнирный цикл (**[v2]** включая все стадии `a/c/n/t` этого цикла, не только карты).
- **[v2]** ~~"EloFinal без пометок"~~ — снято: формула подтверждена, пометка больше не нужна.
- **[v2]** ~~"KD/KR/elo_diff% как предварительные"~~ — снято: формулы подтверждены.
- `avgKills`/`avgKills2` как одна метрика без изменений → **обязательно** пересчитать знаменатель
  на составной ключ (tournament+mapId), легаси-версия искажает результат в среднем в ~7 раз при
  межтурнирном контексте — это не стилистическая правка, а исправление реальной ошибки.
- `_RemainingMatches` (константа 6) → не переносить без внешнего источника расписания
  турнира (см. `docs/unresolved_questions.md` §2.1).
- "Рейтинг команды" как единственное ранжирование → показывать рядом подтверждённое `место на
  турнире`.
- **[v2]** Легаси `_avgADR` (включает untracked-нули) → availability-aware среднее с явным
  "нет данных" там, где карта/турнир не имели трекинга ADR.

## Где линия/bar chart информативнее waterfall

- Динамика Elo за несколько турнирных циклов — линия с накопительной суммой.
- Сравнение прироста Elo команды между циклами — bar chart.
- Waterfall — изменение Elo **внутри одного турнирного цикла** (все карты + стадийные события
  этого цикла).

## Глобальные фильтры

- **[v2]** `tournament_number` (не текстовый код) — глобальный, влияет на все страницы.
- `team` — глобальный (после alias-нормализации).
- `steam_name`/`public_nickname` — не глобальный, локальный поиск на странице Players.
- **[v2]** Опционально — фильтр `rating_stage`, если пользователь хочет видеть отдельно
  калибровку/нормализацию/турнир на одной и той же странице (по умолчанию можно показывать все
  стадии выбранного `tournament_number` вместе, как единую хронологию).

## Показатели, требующие minimum sample threshold

- `ADR`, `KD`, `KR`, значения в `Team × Map`.
- **[v2]** Любая метрика, производная от `result`/`PP` — дополнительно требует "sample" в смысле
  "доля строк с восстановленным/валидным счётом", не только "количество карт" — карта с
  испорченным `result` не должна тихо считаться такой же надёжной, как карта с валидным счётом.
- Правило по умолчанию: < 3 сыгранных карты → визуально помечать как малодостоверные.
