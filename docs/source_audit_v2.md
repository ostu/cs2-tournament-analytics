# Аудит источников — Audit v2

Дополняет, а не заменяет `docs/source_audit.md` (Audit v1). Здесь фиксируется, что изменилось
после появления `powerquery.txt`, `dax.txt` и authoritative-пояснений пользователя по
рейтинговому циклу. Полный разбор M/DAX — в `docs/powerbi_logic_audit.md`; полная семантика
`Na/Nc/Nn/Nt` — в `docs/rating_semantics.md`; воспроизводимые проверки — в
`pipeline/audit_powerbi_logic.py` → `artifacts/audit_v2/*.json`.

---

## 1. Executive summary

- **Главный вывод Audit v1 о неизвестных формулах в основном снят.** `dax.txt` дал точные
  формулы для `KD`, `KR`, `elo_diff%`, `EloFinal`; подтвердил, что `avgKills2`/`KD2`/`KR2` —
  буквальные дубли `avgKills`/`KD`/`KR`. Формулы не придумывались — переносятся из `dax.txt`
  слово в слово, со сверкой на реальных данных.
- **Главная загадка Audit v1 — код `"7n"` — разрешена бизнес-объяснением пользователя.** Это не
  отдельный турнир, а стадия `Nn` (post-calibration blended rating) рейтингового цикла. Формула
  блендинга (`calculate_elo_final`, веса `0.3/0.5/0.2` и т.п.) найдена в notebook и точно
  совпадает с описанием пользователя, включая нормализацию `Σ=N×1000` (подтверждено численно).
- **`mapId + 1` в Power Query — не смысловой сдвиг, а коррекция 0-based/1-based индексации**
  между notebook-экспортом (`range()`, начинается с 0) и таблицей результатов (начинается с 1).
  Подтверждено на всех 13 турнирах/калибровках; со сдвигом соединяется 99.96% строк, без него
  — только 47.7%.
- **Найдена вероятная причина смешанного формата `result`** (счёт/дата): числовой анализ
  показывает, что "даты" в этой колонке — это счета вида `"M-D"` (месяц≤12, день≥13),
  испорченные автоформатом Excel при сохранении `.xlsx` (год испорченной даты точно совпадает с
  реальным годом турнира — не совпадение).
- **Найдены новые, не описанные в Audit v1 проблемы**, специфичные для DAX-слоя: жёстко
  зашитая константа `6` в `_RemainingMatches` не подтверждается ни на одном турнире; деление
  `PP/5` ломается на 5 из 448 карт с составом из 4 игроков; `_avgKills`/`_avgKills2` завышают
  average kills примерно в 7 раз при межтурнирном контексте из-за нелокального `mapId`.
- **PII-контракт и алиасинг команд теперь имеют конкретную, работающую реализацию** (не только
  спецификацию): `data/private/player_aliases.csv` сгенерирован и проверен на идемпотентность
  и отсутствие коллизий; `pipeline/check_publication_leaks.py` проверен self-test'ом;
  `config/team_aliases_review.csv` — 72 кандидата, 4 требуют ручного решения, ложных
  автосклеек (типа "Команда 1"="Команда 2") не допущено.
- **Ничего в `data/raw/` не изменилось** (SHA-256 сверены повторно), сетевые запросы не
  выполнялись, финальный HTML не создавался.

## 5. Проблемы качества данных — обновление

Все проблемы Audit v1 (расхождения в названиях команд, PII в `players.xlsx`, смешанный
`result`) остаются в силе как проблемы **данных**; в Audit v2 к ним добавилось понимание
**причины** для `result` (вероятная порча Excel'ом) и конкретный **инструмент** для команд
(`config/team_aliases_review.csv`). Новые проблемы, найденные только через DAX-слой:

1. `_RemainingMatches=6` — не универсально (раздел 7, `powerbi_logic_audit.md`).
2. `PP/5` — ломается при составе из 4 игроков (5 карт из 448).
3. `_avgKills`/`_avgKills2` — искажение при межтурнирном контексте (мера, а не данные, но
   влияет на то, что видят пользователи текущего Power BI отчёта).
4. `tMapIndex`/`player_elo_diff`/`_startElo` — латентная (не проявившаяся) ошибка при турнирах
   №10+, построенная на нулевом отступе (`Number.ToText([mapId],"00")`) и на однозначных
   номерах турниров.

## 6. Оставшаяся неизвестная Power BI-логика

Полный список — `docs/unresolved_questions.md`. Кратко, что осталось (в Audit v1 было 8+
пунктов "формула отсутствует", теперь):

- точная база для сохранённого `elo_diff` в стадии `Nn` (`"7n"`);
- индивидуальный алгоритм `Na` для турниров 2-5 (агрегат подтверждён, индивидуальные значения
  не сходятся с чистой пропорциональной формулой);
- причина `elo_start=500` у игрока `Player-Delta` (идентификатор анонимизирован) на турнире 5 (единичное исключение из правила
  "новый игрок = 1000");
- реальное плановое число матчей на турнир (для корректной замены `_RemainingMatches`);
- привязка конкретных DAX-мер к конкретным визуалам страниц (нет layout-файла `.pbix`, только
  текст формул).
